<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → `/v1/admin/packs/:id/framework/*` | Admin-authored keys, labels and option lists cross here |
| Framework key → `pois.custom_fields` / `pois.filter_values` JSONB | A framework key becomes a JSON object key on every POI of this pack |
| API → PostgreSQL | Definition create/update/delete queries |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-04 | Tampering | `CreateFieldSchema.fieldKey`, `CreateFilterSchema.filterKey` | high | mitigate | Both keys are constrained to `^[a-z][a-z0-9_]{0,63}$` before they can become object keys on `pois.custom_fields` / `pois.filter_values`, so a prototype-polluting key cannot be persisted. |
| T-01-12 | Tampering | `DELETE .../framework/fields/:fieldId` | high | mitigate | The delete handler touches only `pack_field_definitions` / `pack_filter_definitions`. A test inserts a POI carrying values under the key, deletes the definition, and re-reads the POI to prove `custom_fields` / `filter_values` survived. |
| T-01-03 | Tampering | `api/src/routes/admin/fields.ts`, `api/src/routes/admin/filters.ts` | high | mitigate | Drizzle query builder only; `enumOptions` / `options` are Zod-parsed to a string array before being written as JSONB. |
| T-01-01 | Spoofing | `registerFilterRoutes` | critical | mitigate | Registered only inside `registerAdminRoutes`, inheriting the auth preHandler; it is never mounted on the app directly. |
| T-01-13 | Denial of Service | `options` / `enumOptions` arrays | low | accept | An admin could submit a very large option array. Single-admin tool with a shared credential (D-01) and no untrusted submitters; Postgres JSONB limits bound the damage. Revisit if admin access is ever widened. |
</threat_model>
