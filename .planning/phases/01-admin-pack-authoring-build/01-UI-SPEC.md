# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

This is the **first** UI-SPEC for this project. `admin/` does not exist yet — there is no prior
admin UI to stay consistent with. This contract is the design system's origin point; every later
admin-phase UI-SPEC should treat it as the baseline to extend, not re-derive.

Ran under `--auto` (per `01-CONTEXT.md`, itself gathered in `--auto` mode). No user was
available to confirm choices interactively; every open question below was resolved with a
sensible, spec-consistent default rather than left blank, and is called out for visibility.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn — mandated by `Product Specification.md` §2 ("Web Interface" stack: Next.js + shadcn/ui + Tailwind CSS), not optional/discretionary |
| Preset | **Initialized during 01-01 execution.** The `shadcn` CLI installed at execution time (v4.21.0) replaced the old `style: new-york / default` + `baseColor` init grammar with named presets (`nova, vega, maia, lyra, mira, luma, sera, rhea`) plus a `base` component-library choice (`base`/`radix`/`aria`) — there is no `new-york` preset in this CLI generation. Per this file's own instruction to "generate the equivalent preset string... if the CLI prompts for one," the executor built a custom preset code matching this row's original intent: `baseColor: neutral` (unchanged — still a valid option), `style: nova` (the CLI's own default style, chosen since no named style maps to "new-york"), `radius: small` (denser corners, preserving the "denser layout for data-heavy admin screens" rationale), `font: geist`, `iconLibrary: lucide`, `base: radix` (matches the Component library row below). Preset code: `b2hE` (decode: `npx shadcn@latest preset decode b2hE`; browse: `https://ui.shadcn.com/create?preset=b2hE`). CSS variables and RSC are no longer separate init flags in this CLI — both are on by default for a Next.js App Router project and are confirmed by the `components.json` provenance below. |
| Component library | Radix UI primitives (via shadcn) |
| Icon library | lucide-react (shadcn default) |
| Font | Geist Sans via `next/font/google` — the `create-next-app` default since Next.js 14+; no reason to override for an internal single-admin tool |

**Mode:** Light mode only. Single-admin, internal, desktop-oriented tool — dark mode adds a second
palette to maintain for zero users who've asked for it. Revisit only if that changes.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing (badge padding, input-to-label gap) |
| md | 16px | Default element spacing (form field stacking, card padding) |
| lg | 24px | Section padding (Fields section vs. Filters section) |
| xl | 32px | Layout gaps (page header to content) |
| 2xl | 48px | Major section breaks (between pack detail sub-sections) |
| 3xl | 64px | Page-level spacing (top-level page margin) |

Exceptions: none. This is a desktop-oriented internal tool with no touch-target constraint to
special-case (mouse/keyboard primary input).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 13px | 600 (semibold) | 1.4 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

- **Body** — form input text, table cell text, helper/description text.
- **Label** — form field labels, table column headers, badge text (semibold at small size keeps
  dense admin tables scannable).
- **Heading** — section headings within a page: "Fields", "Filters", "POIs", card titles.
- **Display** — page title: pack name / "New Pack", "Build Pack".

## Color

|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Page background, form/card surfaces, dialog backgrounds |
| Secondary (30%) | `#F4F4F5` (zinc-100) | App shell background, top nav bar, table row striping, disabled/inactive row background |
| Accent (10%) | `#2563EB` (blue-600) | Reserved for: primary CTA buttons ("Sign In", "Save Pack Framework", "Add POI", "Build Pack"), active nav/tab indicator, input focus ring, in-row text links ("view POI") |
| Destructive | `#DC2626` (red-600) | Reserved for: "Remove" buttons on field/filter rows, destructive confirmation dialogs, build-failure banner |

Accent reserved for: primary CTA buttons, active nav/tab state, focus rings, and text links —
nothing else. Do not apply accent to table headers, badges, or card borders.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — Login (D-01) | "Sign In" |
| Primary CTA — Pack Framework (D-03) | "Save Pack Framework" |
| Primary CTA — Add POI | "Add POI" (label becomes "Save Changes" when editing an existing POI) |
| Primary CTA — Pack Build | "Build Pack" |
| Secondary CTA — Framework rows | "+ Add Field" / "+ Add Filter" |
| Secondary CTA — Geocode retry | "Retry Geocode" (on a flagged POI's edit form, re-triggers `POST /v1/admin/pois/:id/geocode`) |
| Empty state heading — Pack Framework | "No fields yet" |
| Empty state body — Pack Framework | "Add a field to start building this pack's data shape." (CTA: "+ Add Field") |
| Empty state heading — POI list | "No POIs yet" |
| Empty state body — POI list | "Add your first POI to start building this pack." (CTA: "Add POI") |
| Error state — Login | "Invalid token — check the value in your `.env` file and try again." |
| Error state — Geocode failure (`ADDRESS_NOT_FOUND` / `LOW_CONFIDENCE_MATCH`) | "We couldn't verify this address. Double-check the street, city, state, and ZIP, then save again." |
| Error state — Ambiguous address (`ADDRESS_AMBIGUOUS`) | "We found more than one match for this address — pick the correct one:" (dialog lists `geocode_candidates`) |
| Error state — Pack build (missing required fields, D-04) | Heading: "Build failed — missing required fields." Body: "Fix these POIs, then build again." Inline table columns: POI Name / Missing Field(s). |
| Error state — Pack build (nothing to build) | "This pack has no geocoded POIs yet. Add or fix POIs before building." |
| Success — Pack build | "Pack built — version {version}, {poi_count} POIs included." |
| Destructive confirmation — Remove saved field/filter | "Remove field/filter": "Remove '{label}'? Existing POI data isn't deleted, but this field/filter won't appear on POI forms until it's re-added." |

## UI Considerations

Applicable state considerations resolved: 8 covered, 3 backstop, 1 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Pack framework field/filter list | ✅ covered | "No fields yet" empty state per Copywriting Contract |
| empty | POI list | ✅ covered | "No POIs yet" empty state per Copywriting Contract |
| error | Login (invalid token) | ✅ covered | Error copy per Copywriting Contract |
| error | Geocode failure on POI save | ✅ covered | Inline error copy under address fields per Copywriting Contract |
| error | Pack build failure (missing required fields) | ✅ covered | Inline failure table per D-04, heading + copy in Copywriting Contract |
| populated | POI list with geocode status badges | ✅ covered | D-02 inline status badges (ok / low_confidence / failed / pending), colors in Color section |
| zero-one-many | Field/filter rows in framework builder | ✅ covered | Repeatable rows per D-03; zero rows renders the empty state above, one-or-many rows just repeat the same row component |
| long-text | `additional_info` field on POI form | ✅ covered | Multi-line textarea, no character limit enforced (spec doesn't specify one) |
| loading | Pack build in progress | 🧪 backstop | "Build Pack" button enters a disabled/spinner state labeled "Building…" while the request is in flight; no separate progress screen — verify visually once built |
| overflow | Long POI name / address in table cells | 🧪 backstop | Truncate with ellipsis + native `title` tooltip on hover — verify visually once the table is built |
| zero-one-many | Ambiguous geocode candidate count | 🧪 backstop | Candidate picker dialog must render correctly whether Smarty returns 2 or many candidates — verify visually against real Smarty responses |
| partial | Ambiguous geocode candidate picker layout | ⚠ unresolved | No wireframe specified for how `geocode_candidates` are presented (radio list vs. cards vs. table); planner should treat "simple radio-select list, one line per candidate address" as an assumption unless a better option surfaces during planning |
