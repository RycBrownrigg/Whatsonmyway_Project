<objective>
Close the review loop for POIs that did not geocode cleanly: an admin spots the flagged badge in
the list, opens the POI pre-filled, corrects the address or picks the right candidate, and the POI
returns to pack-build eligibility — all without a dedicated review-queue screen (D-02).

Purpose: ADMINPOI-02 is the half of geocoding that keeps bad data out of packs. Plan 01-03 flags
a POI; this plan is how the admin un-flags it, and it is what makes plan 01-05's build query
trustworthy.
Output: `PUT /v1/admin/pois/:id`, `POST /v1/admin/pois/:id/geocode` with candidate selection, the
POI edit screen, and the candidate picker dialog.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → `PUT /v1/admin/pois/:id` | Untrusted patch payload against an existing master record |
| Browser → `POST /v1/admin/pois/:id/geocode` | A client-supplied candidate index selecting stored provider data |
| Stored `geocode_candidates` JSONB → `pois.latitude` / `pois.longitude` | Previously-stored provider data is promoted to authoritative coordinates |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-16 | Tampering | `selectedCandidateIndex` handling in `api/src/routes/admin/pois.ts` | high | mitigate | The index addresses only the POI's own stored `geocode_candidates` array; it is bounds-checked and returns 400 `CANDIDATE_INDEX_OUT_OF_RANGE` rather than indexing past the end. The candidate's latitude and longitude are re-parsed as finite numbers before being written. |
| T-01-17 | Tampering | `UpdatePoiSchema` | high | mitigate | `poiTypeId` is not updatable, so a POI cannot be silently moved into a different pack's build set. `status` and every `geocode_*` column are server-derived and are not accepted from the request body at all. |
| T-01-03 | Tampering | `PUT /v1/admin/pois/:id` | high | mitigate | Drizzle query builder only; the merged patch is Zod-parsed before any query is constructed. |
| T-01-07 | Denial of Service | the geocode memo in `api/src/services/geocoding.ts` | medium | mitigate | The memo is bounded by a 15-minute entry age and keyed by a normalized address string; combined with the unchanged-address short-circuit it caps how often an admin session can reach the provider. |
| T-01-01 | Spoofing | `PUT`/`POST` POI routes | critical | mitigate | Both mount inside `registerPoiRoutes`, which is registered only through `registerAdminRoutes` and inherits the shared-token preHandler. |
| T-01-18 | Repudiation | un-flagging a POI | low | accept | With a single shared credential (D-01) there is no per-admin attribution for who accepted a candidate. Accepted for a single-admin product; `pois.updated_at` records when. |
</threat_model>
