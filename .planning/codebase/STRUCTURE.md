## Directory Purposes

**`.planning/codebase/`:**
- Purpose: Houses generated codebase architecture documents for GSD command consumption.
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md (if quality focus), TESTING.md (if quality focus), CONCERNS.md (if concerns focus).
- Key files: Generated by `/gsd-map-codebase` skill; read by `/gsd-plan-phase` and `/gsd-execute-phase`.

**`api/src/`:**
- Purpose: Backend application source code.
- Contains: HTTP server (Fastify), database schema (Drizzle ORM), route handlers (to be added), middleware (to be added).
- Key files: `server.ts` (entry point), `db/schema.ts` (ORM schema).

**`api/drizzle/`:**
- Purpose: Auto-generated SQL migration files.
- Contains: `<timestamp>.sql` files generated by `drizzle-kit generate` (one per schema change).
- Generated: Yes (via `npm run db:generate` after schema edits).
- Committed: Yes (migrations are code).

**`infra/`:**
- Purpose: Local development environment setup.
- Contains: Docker Compose definition for `wowm-db` (PostgreSQL 16) and `wowm-api` (Fastify container).
- Key files: `docker-compose.yml`.
- Run locally via `docker-compose up` for full-stack dev.

**`app/` (not yet created):**
- Purpose: iOS/iPadOS client application.
- Will contain: Expo project structure (src/, app/, assets/, etc.), React Native components, Expo Router navigation, TanStack Query integration, SQLite offline storage.
- Tech stack: Expo, React Native, TypeScript, NativeWind (Tailwind for React Native).
- Will be scaffolded: `npx create-expo-app app --template`.

**`admin/` (not yet created):**
- Purpose: Web interface for pack authoring, master DB management, imports.
- Will contain: Next.js project structure (app/, components/, pages/ if using pages router), pack framework builder, POI import UI, pack build tool.
- Tech stack: Next.js, TypeScript, shadcn/ui, Tailwind CSS.
- Will be scaffolded: `npx create-next-app@latest admin --typescript --tailwind`.

## Key File Locations

**Entry Points:**
- `api/src/server.ts`: Backend API entry point (currently just healthz endpoint; will add all routes from Product Specification §7).
- `app/`: iOS entry point (App.tsx or similar) — not yet scaffolded.
- `admin/`: Admin web entry point (app/layout.tsx or pages/index.tsx) — not yet scaffolded.

**Configuration:**
- `api/tsconfig.json`: TypeScript compiler options (ES2022 target, strict mode enabled).
- `api/drizzle.config.ts`: Drizzle CLI configuration (database URL from DATABASE_URL env var).
- `api/package.json`: Node.js runtime version (>=22), dev/production dependencies, scripts (dev, build, start, db:generate, db:migrate, db:studio).
- `api/.env.example`: Template of required env vars (DATABASE_URL, PORT, Apple App Store config, Smarty API key, etc.).

**Core Logic (Backend):**
- `api/src/db/schema.ts`: Drizzle ORM schema — defines all 12 tables (users, poiTypes, packs, packFieldDefinitions, packFilterDefinitions, pois, packPois, packVersions, entitlements, imports, importRowErrors, feedbackSubmissions).
  - To be split: Once endpoint handlers are added, move route handlers to `api/src/routes/` or `api/src/handlers/`.

**Database:**
- `infra/docker-compose.yml`: Local PostgreSQL 16 container (binds to 127.0.0.1:5432, volume-mounted data at `wowm_db_data`).

## Naming Conventions

**Files:**
- TypeScript files: camelCase (e.g., `server.ts`, `schema.ts`, `userService.ts`).
- Database migration files: auto-generated `<timestamp>.<name>.sql` by Drizzle Kit.
- Environment files: `.env`, `.env.example` (never commit `.env` with secrets).

**Directories:**
- Lowercase, hyphenated where necessary (e.g., `api/src/db/`, `api/src/routes/`).
- Plurals for collections (e.g., `routes/`, `handlers/`, `services/`).
- `src/` as root for application code.
- `dist/` for compiled output (gitignored).
- `node_modules/` for dependencies (gitignored).

**TypeScript / Drizzle Naming:**
- Table definitions: camelCase in Drizzle (e.g., `applySub`, `poiTypeId`) → snake_case in PostgreSQL (e.g., `apple_sub`, `poi_type_id`).
- Table names exported: camelCase (e.g., `export const users = pgTable(...)`).
- Types inferred from schema automatically via Drizzle (no manual type exports needed initially, but add explicit type files when query complexity grows).

**API Route Pattern (to be established):**
- Path format: `/v1/<resource>` (versioned, RESTful).
- Example from spec: `GET /v1/packs`, `POST /v1/purchases/verify`, `GET /v1/packs/:slug/download`.
- Handlers: Suggest organizing in `api/src/routes/` with subdirectories per resource (e.g., `api/src/routes/auth.ts`, `api/src/routes/packs.ts`, `api/src/routes/admin/imports.ts`).

## Where to Add New Code

**New Feature (e.g., adding a route handler):**
- Primary code: `api/src/routes/<resource>.ts` (once created; not yet in structure).
  - Example: `POST /v1/purchases/verify` handler lives in `api/src/routes/purchases.ts`.
- Validation schemas (Zod): `api/src/schemas/<resource>.ts` or inline in handler (start with inline, extract if shared).
- Tests: `api/src/<feature>.spec.ts` or `api/src/__tests__/<feature>.test.ts` (convention TBD once testing scaffold added).

**New Database Table (implies schema change):**
- Add to: `api/src/db/schema.ts` (define table via `pgTable()`).
- Then: Run `npm run db:generate` to auto-generate migration.
- Commit: Both `api/src/db/schema.ts` and `api/drizzle/<timestamp>.sql`.

**New Service/Utility (e.g., Smarty geocoding adapter):**
- Location: `api/src/services/<service>.ts` or `api/src/lib/<utility>.ts`.
- Example: `api/src/services/geocoding.ts` for Smarty integration.

**New Admin Feature (pack framework builder, import UI, etc.):**
- Location: `admin/app/` or `admin/pages/` (structure depends on Next.js router choice).
- Not yet scaffolded; patterns to be established during Phase 4.

**New iOS Screen or Component:**
- Location: `app/app/` (Expo Router) or `app/src/screens/` (structure TBD).
- Not yet scaffolded; patterns to be established during Phase 0 iOS scaffold.

## Special Directories

**`api/drizzle/`:**
- Purpose: Drizzle CLI output — SQL migration files.
- Generated: Yes, via `npm run db:generate` after editing `api/src/db/schema.ts`.
- Committed: Yes.
- Modify by: Never hand-edit `.sql` files; always edit schema.ts and regenerate.

**`infra/`:**
- Purpose: Local development environment.
- Contains: `docker-compose.yml` for `wowm-db` + `wowm-api`.
- Usage: Run `docker-compose up` from `infra/` to start both containers; `wowm-db` at `127.0.0.1:5432`, `wowm-api` at `127.0.0.1:3003`.
- Note: `.env` file in `api/` is sourced by the `wowm-api` container; set `DATABASE_URL=postgres://wowm:wowm@wowm-db:5432/wowm` (note `wowm-db` hostname, internal to Docker network).

**`node_modules/`:**
- Gitignored; install via `npm install` in `api/`.
- Contains: All dependencies (Fastify, Drizzle ORM, Zod, TypeScript, tsx, etc.).

**`.env` files:**
- `.env.example`: Template; commit to repo.
- `.env`: Local secrets; gitignored, never commit.
- Required vars (from Product Specification §3): `DATABASE_URL`, `PORT`, `HOST`, Apple App Store Server API key (`.p8` path), JWT signing secret, Smarty API key.

**`.planning/codebase/`:**
- Generated documentation; refresh via `/gsd-map-codebase` when architecture changes.
- Consumed by `/gsd-plan-phase` and `/gsd-execute-phase` to understand existing patterns.

## Implementation Notes by Phase

**Phase 0 (Foundations):**
- Scaffold `app/` via Expo; implement basic MapKit route + hardcoded POI search (no packs, no IAP).
- Scaffold: Create `app/` directory structure, set up Expo Router, dummy routes/screens.
- API: Scaffold is done; add basic `/healthz` (already done); add a `/v1/app/version` endpoint.

**Phase 1 (Single Pack MVP):**
- API: Add routes for catalog (`GET /v1/packs`, `GET /v1/packs/:slug`), auth (`POST /v1/auth/apple`, `POST /v1/auth/refresh`), entitlements check.
- iOS: Implement route sampling algorithm (Product Specification §10), local SQLite storage, on-device schema migrations, bounding-box + haversine search.
- Geocoding: Integrate Smarty adapter in `api/src/services/geocoding.ts` (or similar).
- Testing: Add unit tests for route sampling and geocoding adapter; establish test patterns.

**Phase 2 (Commerce):**
- API: Add routes for purchase verification (`POST /v1/purchases/verify`), entitlements (`GET /v1/entitlements`, `POST /v1/entitlements/restore`), pack manifest + download (`GET /v1/packs/:slug/manifest`, `GET /v1/packs/:slug/download`), webhook (`POST /v1/webhooks/app-store-notifications`).
- iOS: Implement StoreKit purchase flow, download manager (resumable via Range headers), entitlement refresh, offline token policy.

**Phase 4 (State Packs & Tooling):**
- Scaffold `admin/` via Next.js; implement pack framework builder (fields, filters), pack build trigger UI.
- API: Add admin endpoints (`POST /v1/admin/packs`, `POST /v1/admin/packs/:id/build`, `POST /v1/admin/packs/:id/framework/fields`, etc.).

**Phase 5 (Import Pipeline):**
- API: Add import endpoints (`POST /v1/admin/imports`, `GET /v1/admin/imports/:id`), validation + geocoding pipeline, feedback endpoints (`POST /v1/feedback`, `GET /v1/admin/feedback`).
- Admin: Add import UI (file upload, validation display, error review).
